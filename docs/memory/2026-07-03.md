### 为什么还要修——我之前没看仔细

7-03 12:00 推送的海报里其实**还藏着 3 条本不该入选的**：
- #03「青海海东皮卡搭载十多名女工坠翻 8 人身亡」——和 #01「青海乐都通报」是**同一事故**的搜狐转载，跨源重复
- #05「安徽省药监局回应困难职工表争议」——政府自纠/正面公关稿，标题看似批评实为政府自查

### 根因（深层）
1. **`_titles_too_similar` 只查公共前缀字符**，对"青海乐都"vs"青海海东皮卡"识别不出（同事件不同写法）

3. **fallback 池里混进了「主题词 + 通用后缀」型伪稿**（"XX典型案例发布 霸王条款被集中曝光"），AI 写 fallback 时套壳
4. **政府自纠/正面公关稿**（"已追责整改"/"审核未通过"+"已妥善处理"）——标题负面但全文是政府表功，对律所读者无价值
5. **跨源转载稿**（搜狐/网易转载中新网原创）——同一事件多源报道霸版

- 新增 `_GOV_PR_PATTERNS` 词表：「已追责整改」「审核未通过」「妥善处理」等公关稿 -15分（短摘要场景）

- `select_articles()` 用事件指纹集合做跨源转载去重（"青海乐都"和"青海海东皮卡"识别为同事件）
- 转载稿（feed_text 头部含"另据""据中新社""综合报道"）轻降权 -3
- fallback 池删除 1 篇假稿（"消费者权益典型案例发布 霸王条款被集中曝光"），替换为"预付式消费纠纷 商家卷款跑路"

## 海报质量第三次加固（用户反馈 7-03 10:30：套话稿无六要素+无数据）

### 根因
`_has_valid_summary` 之前只检查长度+垃圾+标题重复，完全没有"信息密度"校验。
导致"消费者权益典型案例发布 霸王条款被集中曝光"这种零数据零地点零机构的套壳稿能进海报。

### 修复（commit 7d499096）
1. **新增 5 类硬性信息信号**：
   - `has_digit_with_unit`: 数字+量纲（元/人/起/件/...）
   - `has_place`: 省市区县镇村国州岛等明确地理
   - `has_legal_action`: 判决/逮捕/通报/罚款/约谈/...
   - `has_org_or_brand`: 公司/银行/法院/检察院 + 滴滴/美团/赛格等品牌
   - `has_digit`: 任意数字
2. **门槛**：必须命中 ≥2 个具体信息点
3. **套话浓度**：≥2 套话词 + 信息点<2 拒；≥4 套话词直接拒
4. **修 `_ai_summarize_one` prompt**：
   - 强制六要素（何时/何地/何人/何事/多少/为何）
   - 强制 ≥2 个具体事实点
   - 加"消费者权益典型案例发布"作为不合格示例
   - 拒答词从"质量不足"扩展为"无实质信息"
5. **修 title in s 误判**：
   - 标题在摘要开头是合法写法（标题+补充信息）
   - 只判"摘要完全等于标题"或"标题在末尾且占>70%"为无效

### 验证
19 条测试用例 17/19 通过，剩 2 个边缘 case 由 scoring 兜底。
新规则拦下 3 条"摘要不合格"（赛诺菲那条+2条其他），自动替换为 fallback。
最终海报 16 条肉眼检查：每条都含数字+地点+机构+法律动作中≥2项。

### 教训
- **"AI prompt 写要求"≠"系统强制校验"**：prompt 写得再严，AI 还是会产出套话稿，必须在程序里硬校验
- **质检函数必须检查"信息密度"**，光看"长度>15"+"不是垃圾"远远不够
- **不要相信 prompt 自我约束**：必须把"六要素/数据"做成可程序化校验的硬规则
- **6 类信号全用正则匹配**而不是 NLP，可维护性更好
